# Part 9 — Tools + Safe Actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agents use journaled, approval-gated, taint-aware tools through a provider-agnostic action loop.

**Architecture:** `app/tools/` holds the framework (Tool ABC, registry, tools.yaml config), the 8 tools,
the SSRF guard, the journal (`tool_calls`) and `ToolLoop`. `BaseAgent.run` delegates to `ToolLoop` only
when the agent has effective tools; the worker injects a `ToolRuntime` and handles the new
`ToolApprovalNeeded` signal (suspend). Every LLM step goes through the Part 8 router.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy async, Postgres 16, Pydantic v2, httpx, trafilatura +
beautifulsoup4, sqlglot, respx (tests), tavily-python (optional backend), ddgs (existing).

**Spec:** `docs/superpowers/specs/2026-11-26-part9-tools-design.md` (read it; rulings 1-6 included).

## Global Constraints
- No `config/tools.yaml` → no agent has tools → behaviour identical to Part 8; all existing tests pass.
- LLM proposes; code validates, authorizes, executes, journals and decides approval.
- Default test suite: no real network (respx / fake backends), `LLM_PROVIDER` fake or FakeLLMClient.
- Secrets never in tool args, `tool_calls` rows, events or logs (redact headers + credential values).
- `MAX_TOOL_STEPS=8`, `MAX_TOOL_OUTPUT_CHARS=4000`, `TOOL_LOOP_TIMEOUT_SECONDS=900`,
  `TOOL_RESULT_REUSE_SECONDS=3600`, web_fetch max 2 MB / 5 redirects, sql row limit 200,
  sandbox `outputs/workspaces/<workflow_id>/`, outbox `outputs/outbox/`.
- Approval mode default: external_write tools `always`; tainted attempt + external_write ⇒ approval
  (code, not configurable).
- Status changes only via `app/core/state_machine.py`; every save keeps the ownership guard.
- Never run two pytest sessions at once. Gemini: at most 3 real calls, at the very end.

## Review Focus
1. A crash between a tool's side effect and its `succeeded` journal update (row stays `running`) →
   unknown_outcome path, never a silent double send. Test in Task 9.
2. The model proposes the same write twice in one attempt with identical args → second is reused,
   not re-sent. Test in Task 9.
3. Approval overrides that fail the tool's input_model → 422, approval stays pending. Test in Task 11.
4. A cancel or immediate pause while a tool is mid-execution → the tool's result is journaled but the
   task result is discarded; no new tool call starts. Test in Task 11.
5. web_fetch to a hostname whose DNS returns one public and one private address → blocked. Test in
   Task 3.
